# 产品规格基线

版本：0.1
状态：初始验收口径；带“待验证”的数值需在基准/真机阶段定稿

## 1. 运行环境

| 项目 | 初始规格 |
|---|---|
| 地面端 | Windows 10/11 64 位笔记本，主要目标 1440×900 与 1920×1080 |
| 最低 UI 验收 | 1280×720，100%～150% Windows DPI 缩放 |
| 空中端 | Windows 64 位轻量机载电脑；具体 CPU/内存/磁盘待硬件冻结 |
| Python | 3.11～3.13；推荐开发基线 3.12 |
| UI | PySide6 + pyqtgraph |
| 数值/存储 | NumPy、SciPy、h5py/HDF5 |
| 设备 | LibreVNA USB、串口 GNSS、HM30 IP 链路 |

## 2. 雷达数据规格

- 支持 S11；数据模型与文件格式从第一天支持 S11/S22 双反射通道及未来 S 参数扩展。
- 频率、点数、IFBW 和通道集合由任务配置显式保存，不在业务代码硬编码。
- 目标扫频范围可能为约 0.4～4.0 GHz，但必须根据实际天线、LibreVNA 和采集速度测试冻结，当前标记为**待验证**。
- 复数频域数据以 `complex128` 领域表示；若线上或文件采用更紧凑编码，必须记录 dtype 并证明精度满足要求。
- 单道频域：`channel × frequency`；连续频域：`trace × channel × frequency`。
- 时域：`trace × channel × time`，时间轴单位为秒；UI 可显示 ns。

## 3. 时间与位置

- 所有持久化墙钟时间采用 UTC 且包含时区语义。
- 调度使用单调时钟，禁止用系统墙钟间隔驱动采集。
- GNSS 经纬度使用 WGS84 十进制度。
- 距离单位 m，时间轴存储单位 s，频率单位 Hz，速度单位 m/s。
- GNSS stale 阈值由配置给出，初始示例为 2 s，不是固定产品常量。

## 4. UI 规格

- 顶部单行菜单；不设置多排常驻参数按钮。
- 中央左侧上下双 B-scan，右侧 GNSS 地图；默认宽度约 68:32，可拖动。
- 地图建议最小宽度 400 px，在低分辨率下可通过“视图”菜单折叠。
- 底部单行状态栏显示：链路、空中端、VNA、GNSS、任务、道数、丢失、待同步。
- A-scan、频域曲线和详细 GNSS 信息是可选 dock/窗口，不常驻默认主界面。
- 交互设置从地面端菜单进入；空中端不提供校准、处理或图形分析界面。

## 5. 数据与恢复规格

- 正式任务文件扩展名 `.rcscan`，格式族 `rcscan`，UAV profile 使用 schema v2。
- 采集中使用 `.partial.rcscan`；完成后 flush、写终态并原子改名。
- 默认每道写入后 flush（可在验证后调整），不得仅在任务结束时整体保存。
- 空中端和地面端都保存完整 `frequency_raw` 与逐道任务/GNSS 元数据。
- 空中端网络待发状态持久化；程序重启后仍可知道未 ACK 道。
- 地面端可读取钢筋仪 `.rcscan` v1；写出 v2 或显式迁移，不伪装为 v1。

## 6. 性能与稳定性初始门槛

以下是开发验收门槛，不替代后续真机基准：

- UI 中任何设备、网络、文件或长计算操作不得占用主线程。
- B-scan 和地图刷新频率与采集解耦，建议显示刷新上限 10～20 Hz，实际值通过基准冻结。
- 10 万道合成任务回放时，UI 视图内存必须有界，不为每一道创建永久重型图元。
- 8 小时模拟采集与断线重连测试中：已确认完整 sweep 不丢失、无哈希冲突被覆盖、进程内存无持续线性泄漏。
- 地面端控制操作在本机无阻塞时应在 200 ms 内给出“已请求/等待远端”反馈；真实命令完成时间单独显示。
- 存储写入和哈希的 p95 耗时必须低于任务最小允许采集间隔，并保留足够余量；具体最小间隔待硬件基准确认。

## 7. 发布门禁

- 无硬件自动化测试全部通过。
- 数据格式和协议契约样本能够往返读取。
- 至少完成一次真实 LibreVNA、GNSS、HM30 联调。
- 完成 HM30 开/关/传输负载四组电磁干扰对照。
- 完成空中磁盘满、地面磁盘满、断网、重连、重复、乱序、冲突和掉电恢复验证。
- 操作手册中的流程与发布构建实测一致。

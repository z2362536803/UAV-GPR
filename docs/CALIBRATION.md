# 校准与参考数据

版本：0.1
状态：目标设计，尚未实现

## 1. 概念边界

- **OSL 校准**修正 VNA 一端口系统误差。
- **空采背景**减去空场/系统环境的复数频域参考。
- **Flat Reflection**是沿测线方向的时域局部背景处理。
- **零时校正**调整时域参考点。

四者目的、输入域和参数不同，不能合并成一个“校正”按钮或处理函数。

## 2. 迁移基线

LibreVNA 校准、双反射 OSL、参考采集状态机、兼容性校验和 `.rcal/.rcbg` 以 `E:\钢筋仪软件开发` 为主要参考。旧 UAV-GPR 的校准/处理不作为迁移来源。

## 3. OSL 工作流

对每个反射测量通道执行 Open、Short、Load 三标准件采集。S11/S22 双反射配置可能形成六个物理采集步骤，UI 必须明确当前端口、标准件、进度和质量，不用“自动校准”掩盖人工切换。

计划流程：

1. 地面端菜单打开校准向导并冻结兼容 sweep 配置。
2. 用户按提示接入标准件。
3. 空中端/本地连接执行指定道数采集。
4. 无 UI 会话模型校验每帧并聚合。
5. 构建误差模型、质量统计和 profile ID。
6. 保存 `.rcal`，主任务显式加载但不自动启用。

向导状态机必须独立于窗口按钮，可由合成数据测试。

## 4. 空采背景

空采参考在明确的输入域采集：`raw` 或 `osl_calibrated`。应用时必须匹配：

- channel/S 参数和顺序；
- 完整频率轴；
- 数据域；
- 若为校准域，匹配 `calibration_profile_id`；
- 设备/天线配置的硬性兼容字段。

环境、离地高度、天线安装和日期等作为重要元数据/警告项，但哪些属于硬拒绝应由实测后冻结。

## 5. 处理顺序

固定基础顺序：

```text
frequency_raw
  -> optional OSL
  -> frequency_calibrated (保存 OSL 后、空采前)
  -> optional air background subtraction
  -> optional frequency bandpass
  -> IFFT
```

不得覆盖 raw；不得对已使用相同 profile 校准的数据再次校准；不得把 raw 域背景应用到校准域。

## 6. 兼容性和质量

加载参考文件只表示文件可读，不表示可用于当前任务。任务开始前给出：

- `compatible`：所有硬性字段匹配；
- `compatible_with_warnings`：硬字段匹配但环境/时间等软字段存在差异；
- `incompatible`：拒绝启用并列出字段级差异。

质量报告至少包含采集道数、稳定性/离群统计、标准件求解残差、非有限值和被拒道数。阈值在算法迁移与真机测试阶段确定。

## 7. 文件与 provenance

`.rcal/.rcbg` 规则见 `DATA_FORMAT.md`。应用到任务后，`.rcscan` 必须保存引用 ID、内容摘要、原文件信息和实际执行阶段记录，使离开原参考文件后仍可审计任务处理历史。

## 8. UI 规则

- 入口位于顶部“校准”菜单。
- 主界面只显示紧凑状态，不常驻六步控制面板。
- 参考文件加载、启用和物理采集是不同动作。
- 开始任务前显示冻结摘要；采集中禁止静默切换 profile。
- 校准向导不得在 UI 主线程调用硬件采集。

## 9. 测试

- 理想 OSL、带噪 OSL、奇异/退化标准件和频率不匹配。
- 双通道顺序、单通道 profile 误用和二次校准拒绝。
- 空采域/profile 不匹配、参考长度不匹配和非有限值。
- `.rcal/.rcbg` 往返、摘要损坏和未知 schema。
- 向导取消、重试、设备错误、部分步骤保留策略和安全关闭。

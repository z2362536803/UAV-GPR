# ADR-0004：空中端采用 store-then-forward

- 状态：Accepted
- 日期：2026-08-21

## 背景

HM30 链路可能断开或抖动。仅把 trace 放进内存发送队列会在断电、进程崩溃或长时断网时丢失待发状态。新需求同时要求采集完成后空中端保留一份数据。

## 决策

每个完整 sweep 在空中端先追加并 flush 到 `.partial.rcscan`，再计算规范 raw hash、提交持久化 outbox，最后尝试发送。地面端只有在校验并持久化成功后才 ACK。网络失败不停止安全本地采集；空中磁盘不可写则安全停止。

重连后依据任务 manifest 和逐道身份/哈希补传。相同索引不同哈希 fail-closed，不覆盖、不成功 ACK。空中副本保留到地面完整验证并由策略/用户确认清理。

## 后果

- 采集最小间隔必须包含本地写盘/flush/hash 开销。
- 需要事务型 outbox 和重启恢复。
- 网络 UI 延迟不影响采集事实，但操作者可能看到滞后，需要清晰状态。
- 双端存储/清理需要容量规划和审计。

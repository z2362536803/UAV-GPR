# GNSS 设计

版本：0.1
状态：目标设计；允许参考旧 UAV-GPR 的唯一生产代码领域

## 1. 参考范围

可以从 `E:\UVA_GPR_system` 参考 GGA/RMC 解析、独立 reader、重连、最近 fix 缓存和 sweep 时间匹配思路。迁移前需冻结源文件哈希，并重新审查单位、时区、线程关闭和异常处理。

旧项目的地图 UI、在线 Leaflet/CDN 和窗口集成不迁移。

## 2. 输入与解析

首版计划至少支持：

- GGA：UTC、经纬度、fix quality、卫星数、HDOP、MSL 高程和大地水准面分离；
- RMC：UTC/日期、状态、经纬度、地速和航向；
- 可配置串口、波特率、超时和允许语句；
- NMEA checksum 验证和结构化拒绝原因。

GGA 的时间只有日内时间，必要时与 RMC 日期或可信系统日期组合。跨午夜、无日期和系统钟跳变必须测试；不能把本机接收时间冒充 NMEA 时间。

## 3. 读取和重连

- 串口运行在独立 worker，增量按行解析，限制最大行长度。
- 解析错误计数并继续；连续 I/O 错误触发有退避的重连。
- 每次重连增加 generation，发布状态但不阻塞雷达采集。
- worker 向线程安全、有界 fix 缓存发布不可变对象。
- 关闭时可取消阻塞读取，确保端口释放和线程退出。

## 4. 有效性

GNSS 状态至少区分：

- `disconnected`：串口不可用；
- `no_sentence`：连接但未收到有效 NMEA；
- `no_fix`：语句有效但无定位；
- `valid`：定位有效且未过期；
- `stale`：存在旧 fix，但相对道时刻超过阈值；
- `invalid`：checksum、范围或字段语义错误。

地图只使用 `valid` 且满足配置质量策略的匹配；其他状态原样保存原因。

## 5. 与雷达道匹配

- 在 sweep 开始/结束记录 UTC 与单调时钟，计算 midpoint。
- 从缓存选择与 midpoint 最近的 fix；优先在同一单调时钟域比较，UTC 用于跨端持久化和审计。
- 保存有符号时间差/年龄、匹配方法和质量。
- 超过 `stale_after_s` 的 fix 不可用于地图当前点，但可作为历史诊断记录。
- 缓存覆盖未来/过去合理窗口；超界后明确 `out_of_range`。

若 GNSS 接收器存在固定延迟，只能通过测量获得的配置/校正应用，并记录 provenance。

## 6. 高程与坐标

- 经纬度为 WGS84 十进制度。
- GGA 高程按 NMEA 定义保存为 MSL，水准面分离单独保存。
- 不把 MSL 高程称为无人机离地高度。
- 如果未来从飞控/测距得到 AGL，建立单独来源和时间匹配模型。
- 地图投影只影响显示，原始存储保持 WGS84。

## 7. 地面显示

- 右侧地图显示当前位置、已采轨迹和当前/选中道。
- 紧凑覆盖层显示 fix、卫星数、HDOP、高程、速度和数据年龄。
- stale/no-fix 用颜色和文字明确告警，不把最后位置继续画成实时位置。
- 选择 B-scan 道时按 `trace_uid` 高亮地图点；选择地图点反向定位 B-scan。
- 无 GNSS 道可在时间/道序列中被选择，并提示“无定位”。

## 8. 测试

- GGA/RMC 正常、南/西半球、空字段、坏 checksum、越界和不同 talker ID。
- 跨午夜、RMC 日期缺失、乱序语句和串口拆行。
- 断开、重连、停止、长行攻击和高频输入下的有界缓存。
- sweep midpoint 前后 fix、正负年龄、stale 阈值和无共同时间基准。
- MSL/AGL 不混用，空字段不生成 0 坐标。

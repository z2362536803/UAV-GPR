# 用户界面设计

版本：0.1
状态：地面端布局已决定，尚未实现

## 1. 设计目标

- 地面端面向大于平板的 Windows 笔记本，优先保证数据可读性和长时间操作稳定性。
- 参考钢筋仪软件的 B-scan-first 风格，减少旧 UAV-GPR 的常驻控制和状态堆叠。
- 主界面只负责查看数据与关键状态；设置、校准、处理和诊断通过顶部菜单进入。
- 空中端尽可能弱化 UI，只显示是否安全采集和是否可靠保存/同步。

## 2. 地面端默认布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 文件  连接  采集  校准  处理  视图  工具  帮助              │
├──────────────────────────────────────┬───────────────────────┤
│                                      │                       │
│          S11 / HH B-scan             │                       │
│                                      │       GNSS 地图        │
├──────────────────────────────────────┤                       │
│                                      │  当前位置、轨迹、道位置 │
│          S22 / VV B-scan             │                       │
│                                      │                       │
├──────────────────────────────────────┴───────────────────────┤
│ 链路｜空中端｜VNA｜GNSS｜任务｜道数｜丢失｜待同步            │
└──────────────────────────────────────────────────────────────┘
```

- 左右使用可拖动 splitter，默认约 68:32。
- 左侧双 B-scan 上下等分，可调整；任务只有一个通道时可以单图占满或显示明确未启用占位。
- 右侧地图默认可见，可从“视图”菜单折叠；折叠后 B-scan 自动占满。
- 地图最小建议宽度 400 px；1440×900 下仍需可用，1280×720 下允许快速折叠。
- 状态栏保持一行，不嵌入滚动日志或大量操作按钮。

## 3. 顶部菜单

### 文件

- 新建任务、打开 `.rcscan`、最近文件；
- 导出、关闭任务、退出；
- 恢复 partial 文件通过明确入口执行，不在打开时自动改写。

### 连接

- 连接/断开空中端；
- 空中端、LibreVNA、GNSS 状态详情；
- HM30 链路诊断和时钟检查。

### 采集

- 采集参数；
- 开始、暂停、恢复、停止；
- 任务说明；
- 空中端存储/outbox 状态。

### 校准

- 加载/卸载 `.rcal`；
- S11/S22 OSL 向导；
- 空采背景采集；
- 加载/卸载 `.rcbg`；
- 兼容性和质量报告。

### 处理

- 显示时窗；
- 频域带通；
- Dewow；
- Flat Reflection；
- 已实现后再加入零时等入口；
- 回放重新处理和 revision 管理。

### 视图

- 双/单 B-scan；
- A-scan、频域曲线；
- GNSS 地图、GNSS 详细状态；
- 光标检查器、色图/动态范围；
- 跟随最新道、重置布局。

### 工具

- 数据完整性检查；
- 空地副本比较；
- 缺道/补传；
- 性能与设备诊断；
- 日志目录和诊断包。

### 帮助

- 操作帮助、字段/单位说明、版本和构建信息。

## 4. B-scan

- 使用 pyqtgraph `ImageItem` 或等价高效图元并原地更新。
- 横轴为 trace index/测线位置（仅在有可靠位置模型时），纵轴默认时间 ns。
- 不经深度标定不显示“深度”。
- 使用有界显示缓冲；完整数据由 storage/回放提供。
- 光标显示 trace UID/index、时间、幅值、GNSS 状态和处理 revision。
- 两通道视图共享 trace 选择和时间范围，但允许各自色阶；联动策略必须可关闭。
- 用户暂停显示刷新不等于暂停采集，UI 要明确区分。

## 5. GNSS 地图

- 显示当前位置、已采轨迹、当前道和选中道。
- 覆盖层仅显示 fix、卫星数、HDOP、MSL 高程、速度和数据年龄。
- 控件限制为缩放、跟随、适应轨迹、底图状态等查看操作。
- GNSS 串口/质量参数放在菜单对话框，不叠满地图。
- stale/no-fix 时停止把旧点当作当前位置，并显示醒目文字状态。
- B-scan 与地图通过 `trace_uid` 双向选择；无定位道仍可在检查器中查看。

具体离线和长轨迹规则见 `OFFLINE_MAP.md`。

## 6. 对话框与状态冻结

- 设置对话框建议 900×650～960×680，并支持滚动和 DPI 缩放。
- 字段按“扫频、时窗、间隔、GNSS、存储”分组，旁边显示单位和推导值。
- 应用按钮先做本地校验；开始任务前显示最终冻结摘要。
- 采集中影响数据契约的字段只读。用户要求改变时，引导停止并新建任务。
- 校准向导独立窗口，不把六步流程塞入主界面。

## 7. 状态和错误呈现

- 状态颜色不能是唯一信号，同时使用图标/文字。
- 链路断开、GNSS 失效、outbox 积压等可恢复状态使用非模态告警。
- 磁盘失败、哈希冲突、配置不兼容等阻止继续的错误使用明确模态决策和持久日志。
- “命令已发出”“空中端已接受”“任务已运行”“任务已完成同步”分别显示，不能都叫“成功”。
- 日志不常驻主界面；状态栏点击可打开过滤后的详细窗口。

## 8. 空中端 UI

计划为单个小窗口或托盘状态页，只显示：

- 地面链路和最后心跳；
- LibreVNA 与 GNSS 状态；
- 当前任务/道数；
- 本地文件、磁盘余量和写入状态；
- outbox 待同步数量；
- 最后错误；
- 安全停止和打开诊断信息。

禁止在空中端加入 B-scan、校准向导、处理参数、地图或任务设计器。无显示器部署时，相同状态必须能通过结构化日志/诊断接口读取。

## 9. 键盘与可访问性

- 常用查看与采集命令提供稳定快捷键，危险操作需要状态确认。
- 菜单和对话框支持键盘导航；文本不依赖固定像素截断。
- 100%、125%、150% 缩放进行截图/交互测试。
- 图形色图至少提供色觉友好选项，告警不只靠红绿区分。

## 10. UI 架构和测试

- `MainWindow` 只组装 menu、layout 和 presenter，不实现采集/网络/存储算法。
- B-scan、GNSS map、status bar、trace inspector 和 dialogs 分模块。
- 通过应用状态模型驱动 action enabled/checked，禁止散落互相矛盾的按钮布尔逻辑。
- Qt 测试覆盖菜单入口、状态转换、DPI/最小窗口、地图折叠、双向选择和 worker 结果版本丢弃。

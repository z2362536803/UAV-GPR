## 1. 决策记录（本轮钉死的契约语义）

1. **schema 级 fail-closed vs 数据级报告**：格式/版本/profile/role/lifecycle/dtype/maxshape/chunks/compression/固定轴长度/必需列缺失/config 摘要/axis 契约/checkpoint（`committed_record_count ∈ [0, 最短必需列长度]`、`last_trace_index`、`updated_utc`）→ 打开时 `DomainError` 拒绝；逐道数据问题（缺 hash、hash 不一致、行解码失败、重复、冲突、缺道、checkpoint 语义异常）→ 进入 `ValidationReport` 报告。依据：ISSUE-014 需要能打开并分类含冲突的文件，因此冲突不得使整文件不可读。
2. **冲突 fail-closed 语义**：同 `trace_index` 多份拷贝 hash 不同，或同一 `trace_uid` 出现在不同 `trace_index` → 逻辑视图**排除**该身份（绝不静默选一份）；`trace_by_index` 对冲突索引抛 `DomainError(ID_CONFLICT)` 并携带证据（positions/hashes/uids）；`ConflictTrace` 保留全部证据。物理视图仍按提交顺序呈现全部已提交行（证据可见）。
3. **重复语义**：同 index + 同 uid + 同 hash 的多份拷贝 → `DuplicateTrace` 报告，逻辑视图只服务**首个提交位置**（确定性），物理视图全部呈现。
4. **缺道定义**：`missing = [0, max 已解码 trace_index]` 区间内的空洞；不按 `planned_trace_count` 推测（避免用户停止任务的误报），`planned_trace_count` 原样放入报告供 ISSUE-014 判断。
5. **可见窗口**：只暴露 `< committed_record_count` 且行解码成功的记录；列长度短于 checkpoint → 打开即拒绝（writer 不可能产出该状态，视为损坏）；列长于 checkpoint → 半写尾部，计数可见（`physical_record_count`）但不可读。
6. **awaiting_rename 呈现**：`lifecycle_state=finalized/recovered` 且文件名仍为 `*.partial.rcscan` → `rename_pending=True`，按已完成任务读取（completion_kind 原样呈现），绝不误判为 `writing` 未完成任务；完整识别/处置移交 ISSUE-012。
7. **可选 processed 组**：`time_base/time_processed/calibrated` 缺失合法；存在则与其他数据集同样按冻结契约校验（dtype/maxshape/chunks/compression/形状）。
8. **hash 重算输入**：HDF5 `<i8` 列回读的 `trace_index` 是 `np.int64`，调用 `compute_raw_trace_sha256` 前强制 `int()`（ISSUE-009 R3 剩余风险 5）；raw 以 `<c16` 连续视图进入 framing。
9. **config 重建走公共 API**：存储的 canonical `config_json` 不含 `created_utc/config_sha256`，reader 注入 mission 级两值后走 `MissionConfig.from_dict`（其内部 fail-closed 校验 digest），再核对 canonical 文本一致。
10. **数据集契约校验本地镜像**：`rcscan_v2._validate_dataset_against_contract` 保持私有且本 Issue 不得修改该模块，reader 内置等价的 `_validate_present_dataset`（注释指向权威来源）；这是范围约束下的最小重复，留 P3 级提示供复审。
